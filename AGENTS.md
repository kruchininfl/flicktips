# AGENTS.md

Movie recommendation site (flicktips.ru). No root package/workspace config — each
subproject is installed and run independently from its own directory.

## Layout

- `web/` — SSR React/Redux app (React 16 + react-router 3 + redux-oauth). Express
  server renders React to `views/app.ejs`; webpack bundles the client.
- `api/` — PHP Silex REST API (`/api/...`) powering `web/`. Entry `api/web/index.php`
  → `api/app/app.php`; routes in `api/app/routing.php`, DI in `api/app/services.php`.
- `ft-parser/` — TypeScript parser (rutor → TMDb/Кинопоиск/FastTorrent), runs hourly.
- `kp-parser/` — Babel/Node parser for Кинопоиск metadata.
- `tools/` — shared Babel config only. `mobileApp/` (Cordova), `design/`, `proxy/`,
  `adv/`, `mysql-queries/` are legacy/assets, not part of the build.

## Commands

- Local stack (preferred): `tools/local.sh up` from the repo root → https://flicktips.local
  (needs `127.0.0.1 flicktips.local` in `/etc/hosts` and mkcert; the script issues the cert).
  Runs `docker-compose.local.yml` (web SSR + webpack-dev-server :8050 on Node 16, php-fpm API,
  nginx; all share `web`'s network namespace like prod's host network). No local DB: the API
  uses `flicktips_test` on the server via an SSH tunnel on host `127.0.0.1:3307` (reused if
  already open). Needs the secrets in `.env`, SSH to the server and `docker compose`.
  `tools/local.sh down` / `logs [svc]`. Parsers are not included. VK login only works if the
  local URL is allowed in the VK ID app (VK ID requires https, hence the local TLS).

The rest run inside the subproject dir (`npm install` first; there is no root install).

- web dev without Docker: `npm run nodemon` (server) + `npm run webpack-devserver` (assets on
  :8050); needs Node 16
- web prod build: `npm run build`; serve with `npm run server` (needs `src/hash.txt`,
  which is committed and regenerated by the build)
- api: `composer install` in `api/` (vendor is shipped but untracked)
- ft-parser: `npm start` (`rm -rf dist && tsc && node dist/app.js`) or `npm run dev`
- kp-parser: `npm start` (`node _app.js`, loads `babel-core/register` then `app.js`)
- Lint/typecheck: no lint or test scripts exist. ESLint (v3) runs only through webpack
  in non-production; `tsc` typechecks `ft-parser`. Do not assume `npm test` exists.

## Gotchas

- Import paths use `NODE_PATH=./src` (webpack `resolve.modules`): `import config from
  'config'`, `components/...`, `redux/...`. Aliases only work inside `web/`.
- `web/src/server.js` (SSR) and `web/src/client.js` are separate entrypoints; routes are
  built by `routes(store)`, and redux-oauth `initialize` runs on both sides.
- `web/src/config.js` builds the API/OAuth/socket URLs from `SITE_URL` (env on the server,
  webpack DefinePlugin in the bundle), defaulting to `https://flicktips.ru`.
  `NODE_ENV=cordova` switches the client to hash history.
- `web/.eslintrc` is strict and non-standard: single quotes, `semi` always but
  `eol-last: never`, `object-curly-spacing: never`, `no-var`, `prefer-const`,
  `max-len 128`, 2-space indent. Match it when editing `web/src`.
- Secrets (DB password, VK OAuth, TMDb and kinopoiskapiunofficial keys, TMDb
  proxy) come from environment variables, never from code: `env_var()` in `api/app/config.php`,
  `env()` in `ft-parser/src/core/env.ts` and `kp-parser/components/env.js`. The list lives in
  `.env.example`; compose loads `.env` (`env_file`) into api, ft-parser and kp-parser, and
  php-fpm keeps them via `clear_env = no`. Docker Hub images are public, so a secret added
  to code leaks — add it to `.env.example` instead. Old values remain in git history.
  API chooses `flicktips` vs `flicktips_test` DB by `APP_ENV=dev` (or the old `HTTP_HOST`
  check); `DB_HOST`/`DB_PORT` default to `127.0.0.1:3306`.
- ft-parser `npm start` deletes `dist/` and connects to the production DB; it also hits
  external sites. Prefer `npm run dev` for local work.
- `kp-parser/components/parser.js` imports deps via relative `../node_modules/...` paths
  and toggles Tor/proxy via `ENABLE_TOR`/`ENABLE_PROXY` constants.
- `kp-parser` uses `mysql2@3.x` (needed for MySQL 8.4 `caching_sha2_password`); its entry
  still loads `babel-core/register`, so `require('mysql2/promise')` must stay CJS-compatible.
- Repo remote is GitHub (`kruchininfl/flicktips`, default branch `master`); it moved from Bitbucket.

## Deploy

GitHub Actions (`.github/workflows/deploy.yml`) runs `tools/deploy.sh` on every push to
`master`; a manual run (Actions → Deploy → Run workflow) can rebuild only some services or roll
back. The same script still works by hand from a dev Mac (needs `docker login` as
`infamoustill`). The server only runs Docker Compose (pm2 was removed).

- Workflow secrets (environment `production` or repo level): `DEPLOY_SSH_KEY` (private key
  for the server), `DEPLOY_KNOWN_HOSTS` (`ssh-keyscan` line of the server), `DOCKERHUB_TOKEN`
  (Docker Hub access token of `infamoustill`); optional `DEPLOY_HOST`, `DEPLOY_PATH` override
  the defaults below. In CI the build uses the GitHub Actions cache (`BUILDX_CACHE=gha`).
- Server: `root@45.15.252.159`, project in `/var/www/flicktips.ru`. 1 vCPU, <1 GB RAM,
  ~20 GB disk that is nearly full — never build images there.
- `tools/deploy.sh [service...]` builds images locally for `linux/amd64` (`docker buildx`,
  no compose needed locally), tagged with the commit SHA, and pushes them to Docker Hub
  (`infamoustill/flicktips-*`, public). It then rsyncs `docker-compose.yml`, `.env.example`
  and `docker/`, prunes older flicktips images on the server and runs
  `docker/deploy.sh up <sha> <services>`, which checks `.env` against `.env.example`, pulls
  the new images and recreates containers; finally it curls the site and `/api/`. Services
  not listed are re-tagged from the current release, so one `TAG` always covers all five.
- Do not upload images straight to the server (`docker save | ssh`): uploads from abroad to
  it are throttled to ~50 KB/s, while its pulls from Docker Hub are fast.
- Requires a clean tree (`ALLOW_DIRTY=1` adds a `-dirty` tag suffix). Nothing runs lint or
  tests first; build `web` / `tsc` ft-parser locally if in doubt.
- Server state: secrets plus `TAG`/`PREV_TAG` in `/var/www/flicktips.ru/.env`; only the
  current and previous images are kept. Rollback: `tools/deploy.sh --rollback`.
- Compose services (`web`, `api`, `kp-parser`, `ft-parser`, `nginx`) all use
  `network_mode: host`, so they reach the host MySQL (`127.0.0.1:3306`) and loopback ports:
  web `:3001`, php-fpm `:9000`, nginx `:80/:443`. tg-brew stays on `:3002`.
- Note: some committed `package-lock.json` files are `lockfileVersion 2` (npm 7/8); the
  Node 16 build images handle them.
